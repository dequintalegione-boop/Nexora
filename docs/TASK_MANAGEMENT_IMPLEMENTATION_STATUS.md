# Статус реализации менеджера задач Nexora

Документ фиксирует фактическое состояние кода. Требования из `TASK_MANAGEMENT_PLAN.md` не считаются реализованными только потому, что описаны в спецификации.

Последнее обновление: 2026-11-27
Основная ветка: `main`

## Реализовано в main

- Подключена актуальная точка входа приложения с TanStack Router.
- Миграция данных из старой Dexie/IndexedDB-модели в Zustand (исходная база не удаляется).
- **Версионируемая схема persisted-профиля** (`schemaVersion`, сейчас **v2**): `src/lib/nexora/migrate.ts`, последовательные миграции v0→v1→v2, резервный снимок в `localStorage` перед миграцией, подключение в `merge`/`replaceAll` store и в JSON-экспорт. Unit-тесты идемпотентности и round-trip.
- Гидратация persisted store, таймер (старт/пауза/продолжение/завершение), сессии с привязкой к задачам.
- Модель задачи: даты и временные блоки, несколько проектов, контексты, метки, напоминания, ссылки, повторения, архив и корзина.
- Архив / восстановление / корзина / окончательное удаление; родительские задачи, подзадачи, зависимости без циклов.
- Представления списка, таблицы и Kanban (группировка по статусу, приоритету, проекту).
- Сохраняемые пользовательские представления, колонки, массовые операции, шаблоны задач (локально в UI-профиле).
- **Локальные автоматизации задач:**
  - триггеры: создание, смена статуса, завершение, **`task.due`**, **`task.due_soon`** (`daysBefore`);
  - условия: статус, приоритет, проект, метка, название; вложенные группы AND/OR;
  - действия: статус, приоритет, проект, метки, срок через N дней;
  - UI: несколько условий, И/ИЛИ, предпросмотр правила с dry-run, журнал запусков с фильтром;
  - планировщик раз в 15 с и при фокусе вкладки.
- Быстрый ввод: относительные даты, дедлайн, приоритеты, метки, контексты, время `в ЧЧ:ММ` / `с … до …`.
- **Каталог статусов и приоритетов (настраиваемый):**
  - типы `StatusDefinition` / `PriorityDefinition`;
  - настройки: переименование, скрытие, порядок, добавление своих статусов/приоритетов, категория (open / done / cancelled);
  - хелперы `getActiveTaskStatuses`, `isDoneStatus`, `isCancelledStatus`;
  - миграция v1→v2 материализует каталоги;
  - `setTaskStatus` в store использует `isDoneStatus` (кастомные «готово» выставляют `completedAt` и запускают recurrence/automations).
- Напоминания задач и системные уведомления при открытом приложении.
- Расширенный конструктор фильтров AND/OR; календарь (месяц, неделя, повестка 14 дней); повторения daily/weekly/monthly/yearly.
- **Единый active-каталог в пикерах:** `getStatusSelectOptions` / `getPrioritySelectOptions` (active + текущее значение, если скрыто); применены в диалоге задачи, списке/таблице, массовых операциях, фильтрах и автоматизациях.
- **Политика удаления custom-статуса/приоритета:** задачи с удаляемым id переводятся на fallback (`getFallbackStatusId` / `getFallbackPriorityId`: inbox / first open / first; none / first visible).
- **Расширенный NLP быстрого ввода:** дни недели («в понедельник», «до пятницы»), именованные даты («15 декабря»), оценка («30 минут», «2ч»), проект (`+Название`), статус (`*в_работе`); unit-тесты.

## Автоматические тесты

Покрыты: шаблоны, автоматизации (AND/OR, `task.due`, `task.due_soon`), миграции схемы, каталог статусов (в т.ч. select options и fallback), напоминания, фильтры, Kanban, календарь, быстрый ввод (в т.ч. weekdays/estimate/project/status), повторения.

CI: unit-тесты, TypeScript typecheck, production build.

## Частично реализовано

- Полный TaskRepository/TaskService и единая доменная шина событий отсутствуют.
- Автоматизации: нет глубокого визуального редактора дерева условий и расширенного поиска по журналу.
- Повторения без полного RRULE / виртуальных экземпляров / DST-тестов.
- Таймер без ручной корректировки и Pomodoro-конструктора.

## Ещё предстоит

## Правило готовности

Функция считается завершённой только после проверки сохранения данных, граничных сценариев, связей, миграций и регрессий в обоих поддерживаемых режимах хранения.
